## 2. 项目背景

短视频内容生产需求持续增长，编导团队每天需要围绕不同产品卖点，产出多个短视频选题和脚本，并交付给剪辑、直播和投放团队执行。

现有流程主要依赖人工完成：

```text
产品/运营提供卖点 -> 编导人工想选题 -> 编导人工写脚本 -> 手动整理表格 -> 交给剪辑、直播和投放团队执行
```

当前流程暴露出以下问题：

1. 编导需要从零理解产品、拆解卖点、构思选题和撰写脚本，前期创意发散和初稿生产耗时较长。
2. 不同编导对同一卖点的理解和表达方式不一致，导致脚本质量不稳定，容易出现卖点表达不清、口播不自然、转化引导弱、分镜不可执行等问题。
3. 优质脚本没有形成结构化沉淀，往往散落在表格、文档或聊天记录中，后续难以复用。
4. 投放后的播放、点击、转化、ROI、评论反馈等数据没有有效回流到脚本生产环节，团队难以判断哪些选题、结构和表达方式更有效。
5. 编导、运营、剪辑、直播和投放之间协同成本较高，脚本交付格式不统一，容易产生返工。

因此，本工具希望通过 AI 生成能力和结构化流程设计，将短视频脚本生产从“人工经验驱动”升级为“标准化输入 + AI 辅助生成 + 人工审核 + 脚本资产沉淀 + 数据反馈优化”的内容生产工作台。

## 3. 产品定位

### 3.1 产品定义

AI 编导脚本生成工具是一个面向短视频内容生产团队的 AI 辅助工作台，帮助团队完成从内容任务创建、产品卖点结构化、选题生成、脚本初稿生成、风险初筛、人工审核、脚本入库、导出交付到数据反馈的完整流程。

本产品不是单点 AI 文案生成器，而是服务内容生产链路的协同工具。

### 3.2 核心价值

| 价值方向 | 说明 |
| --- | --- |
| 提升初稿效率 | AI 辅助完成卖点拆解、选题生成和脚本初稿生成，降低编导从零创作成本 |
| 标准化信息输入 | 将运营提供的零散卖点结构化为目标用户、用户痛点、使用场景、证明材料、价格权益和合规限制 |
| 提升交付质量 | 输出口播、分镜、字幕重点、素材建议、转化口播和风险提示，减少后续沟通返工 |
| 沉淀脚本资产 | 保存审核通过脚本，并通过产品、平台、内容目标、选题类型、效果标签等字段支持复用 |
| 数据反哺生产 | 将投放数据和退回原因回流到脚本库、Prompt 模板和风险词库，持续优化内容生产方法 |

### 3.3 MVP 目标

MVP 阶段重点验证一条核心链路：

```text
任务创建 -> 产品信息录入 -> AI 卖点拆解 -> AI 选题生成 -> AI 脚本生成 -> 风险词初筛 -> 人工编辑审核 -> 脚本版本保存 -> CSV/Excel 导出
```

MVP 不追求自动剪辑、自动投放、复杂权限、多平台投放系统对接或模型训练，优先验证 AI 生成结果是否能被编导小修后使用，以及是否能降低内容生产和交付成本。

### 5.4 当前完成度判断

截至 2026-06-06，当前项目已达到“P0 可演示闭环”状态：用户可以创建任务、录入产品信息、拆解卖点、生成选题、选择选题、单条或批量生成脚本、选择最终脚本、完成风险初筛和质量评分、人工审核保存版本，并按全量或勾选范围导出 CSV/Excel。

P0 仍建议继续增强的点：

- AI 输出稳定性：继续强化空标题、空 Hook、空口播、字段格式错误时的兜底和重试策略。
- 批量脚本体验：继续优化批量脚本较多时的浏览、选择、评分和风险初筛反馈。
- 审核闭环：补充结构化退回原因、审核备注和 AI 重写指令之间的联动。
- 导出可控性：补充导出字段配置、导出记录查看和导出文件命名规则。
- 数据一致性：保证 Supabase 与本地 fallback 的字段含义、时间字段和版本记录完全一致。

P1 当前处于“初步完善”阶段：优秀脚本库、质量评分、数据回填、数据复盘和多平台生成策略已经具备初版能力，但高级检索、效果标签体系、Prompt 模板后台、素材资产管理和平台策略运营化尚未完整产品化。

## 6. 核心业务流程

### 6.1 主流程

```text
创建内容任务
-> 产品卖点录入
-> AI 卖点拆解
-> AI 生成选题池
-> 编导筛选选题
-> AI 单条或批量生成脚本
-> 编导选择最终脚本
-> 风险初筛与质量评分
-> 人工审核修改
-> 脚本版本保存
-> 脚本入库
-> 全量或部分导出交付
-> 投放数据回填
-> 效果标签沉淀
-> 模板优化
```

MVP 阶段做到“导出交付”为止，并保留投放数据回填和数据复盘的初版入口。P1 继续建设效果标签、脚本检索、模板优化和素材资产管理。

### 6.2 状态流转

```text
待创建 -> 待录入产品信息 -> 待拆解卖点 -> 待生成选题 -> 待筛选选题 -> 待生成脚本 -> 待选择脚本 -> 待风险初筛 -> 待质量评分 -> 待审核 -> 小修中 -> 已通过 -> 已导出
```

退回重写流程：

```text
待审核 -> 退回 AI 重写 -> 重新生成 -> 待审核
```

P1 投放流程：

```text
已导出 -> 已投放 -> 待回填 -> 已回填 -> 已复盘
```

### 6.3 当前核心链路页面口径

当前页面使用顶部固定核心链路进行导航，并用颜色区分 P0 和 P1：

- P0 核心链路：T1 任务创建、T2 产品信息、T3 卖点拆解、T4 选题生成、T5 脚本生成、T6 风险初筛、T7 人工审核、T8 版本保存、T9 导出。
- P1 增强能力：质量评分、优秀脚本库、数据复盘。

右侧主工作区按顺序展示模块。每个模块应保持固定窗口高度，内容较多时在模块内部滚动、分页或轮播，不应因内容多少改变整个页面结构。

## 7. 功能需求

### 7.1 内容任务创建

#### 输入字段

| 字段 | 类型 | 是否必填 | 示例 |
| --- | --- | --- | --- |
| 任务名称 | 文本 | 是 | 618 洁面乳短视频脚本 |
| 业务目标 | 单选 | 是 | 种草 / 转化 / 直播引流 / 品牌曝光 |
| 产品名称 | 文本 | 是 | 氨基酸洁面乳 |
| 目标用户 | 文本 | 是 | 18-30 岁油敏肌女生 |
| 投放平台 | 单选 | 是 | 抖音 / 小红书 / 视频号 / 快手 / B站 |
| 内容形式 | 单选 | 是 | 口播 / 测评 / 对比 / 剧情 / 直播切片 |
| 脚本数量 | 数字 | 是 | 5 |

| 字段 | 类型 | 是否必填 | 说明 |

| 价格权益 | 多行文本 | 否 | 价格、优惠、赠品、活动信息 |
| 证明材料 | 多行文本/附件 | 否 | 检测报告、用户反馈、品牌背书等 |
| 平台限制 | 多行文本 | 否 | 不同平台表达要求 |
| 禁止表达 | 多行文本 | 否 | 禁止使用或慎用表达 |
| 合规要求 | 多行文本 | 否 | 行业限制和审核要求 |

#### 输出结果

### 7.3 AI 卖点拆解

#### 功能说明

AI 根据产品信息，将运营语言转化为编导可用的脚本语言。

#### 输出字段

| 字段 | 说明 |
| --- | --- |
| 用户痛点 | 用户为什么需要这个产品 |
| 使用场景 | 用户在什么场景下会产生需求 |
| 核心利益点 | 产品能给用户带来的直接价值 |
| 证明材料 | 哪些内容可以增强可信度 |
| 可用表达 | 可以安全使用的表达方式 |
| 风险表达 | 可能存在合规风险的表达方式 |
| 待人工确认信息 | 价格、功效、证明材料、活动规则等需要人工确认的信息 |

#### 输出格式示例

```json
{
  "pain_points": [],
  "scenarios": [],
  "benefits": [],
  "proof_points": [],
  "safe_expressions": [],
  "risky_expressions": [],
  "needs_confirmation": []
}
```

### 7.4 AI 选题生成

#### 功能说明

AI 根据任务目标、平台、目标用户、内容形式和卖点拆解结果，批量生成可供编导筛选的选题池。

#### 选题类型

| 类型 | 适合场景 | 示例 |
| --- | --- | --- |
| 痛点型 | 转化投放 | 为什么你洗完脸总觉得紧绷？ |
| 测评型 | 种草内容 | 油敏肌洁面实测：洗完到底拔不拔干？ |
| 对比型 | 产品差异明显 | 便宜洁面和温和洁面的区别在哪？ |
| 场景型 | 日常消费品 | 熬夜后满脸油，早上怎么洗才舒服？ |
| 反常识型 | 提高停留 | 脸越洗越油，可能不是你没洗干净 |
| 直播引流型 | 直播间转化 | 今晚直播间这支洁面适合哪些人抢？ |

#### 每个选题输出字段

| 字段 | 说明 |
| --- | --- |
| 选题标题 | 给编导看的方向 |
| 前 3 秒 Hook | 用于吸引用户停留 |
| 内容角度 | 痛点、测评、对比、场景等 |
| 适合平台 | 抖音、小红书、视频号等 |
| 推荐理由 | 为什么适合这个产品 |
| 风险提示 | 是否存在表达风险 |
| 拍摄难度 | 低 / 中 / 高 |

#### 当前交互要求

选题池使用卡片分页展示，用户可自定义每页展示数量。卡片高度保持一致，内容较长时在卡片内部滚动，选择按钮固定在卡片底部，避免用户必须读完整张卡片才能看到操作入口。

当用户点击“选择此选题”后：

- 当前选题应有明确选中状态。
- 单条生成脚本时只针对已选选题生成。
- 批量生成脚本时仍可生成多条，但默认浏览位置应切到已选选题对应的脚本，不应丢失用户选择上下文。

内容角度和拍摄难度需要提供 hover 解释：

| 字段 | 解释口径 |
| --- | --- |
| 内容角度 | 说明该选题属于痛点、场景、测评、对比、直播引流等哪类切入方式 |
| 拍摄难度：低 | 常规产品实拍、口播或已有素材即可完成 |
| 拍摄难度：中 | 需要补充证明材料、场景画面或轻度拍摄设计 |
| 拍摄难度：高 | 需要更强素材、复杂分镜、达人配合或更严格合规确认 |

### 7.5 编导筛选选题

#### 功能说明

编导从 AI 生成的选题池中选择适合本次任务的方向，进入脚本生成环节。

#### 筛选维度

| 维度 | 判断标准 |
| --- | --- |
| 是否符合业务目标 | 是否适合种草、转化或引流 |
| 是否贴合目标用户 | 用户是否有真实痛点 |
| 是否适合平台 | 是否符合目标平台内容风格 |
| 是否可拍摄 | 是否能在现有素材和条件下完成 |
| 是否有风险 | 是否涉及夸大、医疗化或绝对化表达 |
| 是否有差异化 | 是否避免同质化内容 |

### 7.6 AI 脚本生成

#### 功能说明

选题确定后，AI 根据固定脚本结构生成初稿。

#### 脚本结构

1. 前 3 秒 Hook；
2. 用户痛点放大；
3. 产品卖点切入；
4. 场景化说明；
5. 信任补充；
6. 转化行动引导。

#### 输出字段

| 字段 | 使用角色 | 说明 |
| --- | --- | --- |
| 口播脚本 | 编导 / 主播 | 完整口播内容 |
| 分镜建议 | 剪辑 / 拍摄 | 每个时间段画面怎么呈现 |
| 字幕重点 | 剪辑 | 哪些句子需要突出 |
| 素材建议 | 剪辑 / 拍摄 | 产品特写、对比画面、场景素材等 |
| 转化口播 | 投放 / 主播 | 引导点击、购买、进直播间 |
| 合规提醒 | 审核人 | 需要人工确认的风险表达 |
| 待确认信息 | 审核人 | 价格、功效、证明材料等需确认内容 |

#### 输出格式示例

```json
{
  "title": "",
  "hook": "",
  "spoken_script": "",
  "storyboard": "",
  "subtitle_points": [],
  "material_suggestions": [],
  "conversion_cta": "",
  "risk_notes": [],
  "needs_confirmation": []
}
```

#### 当前交互要求

脚本生成支持两种方式：

| 方式 | 说明 |
| --- | --- |
| AI 生成脚本 | 基于当前已选选题生成单条脚本 |
| 批量生成脚本 | 基于当前选题池批量生成多条脚本，数量与任务脚本数量或选题池数量一致 |

批量生成脚本后，用户必须可以在脚本列表中切换浏览，并点击“选择此脚本”确认最终进入质量评分、风险初筛、审核和版本保存的脚本。

选择脚本后的联动：

1. 当前脚本进入质量评分。
2. 当前脚本进入人工审核默认对象。
3. 批量生成的其他脚本仍保留在浏览列表中，不应被覆盖为单条。
4. 用户点击“AI 重新生成”时，如果处于批量脚本上下文，应优先保留批量列表，只重写当前脚本或按用户明确动作批量重写。

脚本模块采用固定窗口 + 模块轮播方式展示。建议模块包括：

- 口播脚本；
- 分镜建议；
- 字幕重点；
- 素材建议；
- 转化口播；
- 合规提醒；
- 待确认信息。

当 AI 返回的分镜建议为空或结构不完整时，兜底分镜必须结合当前选题标题、Hook、用户痛点、使用场景、产品卖点和证明材料生成具体镜头，不允许只展示“人物口播开场”“展示产品和使用场景”等通用占位描述。

当 AI 返回字段为空或格式不完整时，系统应基于选题标题、选题 Hook、内容角度和产品卖点进行最低可用兜底，避免出现“未命名脚本”、空 Hook 或空口播。

### 7.7 风险词初筛

#### 功能说明

系统对 AI 生成脚本进行风险初筛，标记潜在风险表达，并给出替代表达建议。

#### 检查类型

| 风险类型 | 示例 |
| --- | --- |
| 绝对化表达 | 最好、第一、永久、彻底 |
| 夸大承诺 | 立刻见效、马上变白、根治 |
| 医疗化表达 | 治疗、修复疾病、改善炎症 |
| 价格误导 | 全网最低、错过不再有 |
| 资质风险 | 未经确认的认证、检测、背书 |

#### 实现方式

MVP 阶段采用“规则词库 + 大模型复核”的方式：

1. 规则词库扫描脚本文本，标记命中风险词。
2. AI 根据命中风险词解释风险原因。
3. 系统给出建议替代表达。
4. 人工审核时可确认风险、修改文本或标记误报。

当前 MVP 已实现规则词库扫描，并展示风险词库的筛选依据。风险扫描范围包括标题、Hook、口播脚本、字幕重点和转化口播，不扫描内部合规提醒字段本身，避免把“禁止使用治疗、根治”等内部提示误判为脚本违规。

批量脚本场景下，风险初筛需要按脚本分组展示：

- 先展示每条脚本命中数量和风险摘要；
- 用户可切换查看某一条脚本的详细命中；
- 命中文本需要在脚本定位区域高亮；
- 当脚本数量较多时，风险列表使用选择器或滚动容器，不应堆满页面。

当前风险词库初始规则包括：

| 类型 | 示例词 | 处理方式 |
| --- | --- | --- |
| 绝对化表达 | 最好、第一、永久、彻底 | 建议替换为更适合日常使用、表现较突出等相对表达 |
| 夸大承诺 | 立刻见效、马上变白、根治 | 建议替换为体验感受或需结合真实依据的表达 |
| 医疗化表达 | 治疗、炎症、修复疾病 | 建议改为护理、舒缓、改善体验等非医疗表达 |
| 价格误导 | 全网最低、错过不再有 | 建议以页面实际活动信息为准 |
| 资质风险 | 未确认认证、检测、背书 | 要求运营提供证明材料后再使用 |
| 贬损表达 | 外貌羞辱、低俗比喻、攻击性称呼 | 禁止使用，改为中性痛点描述 |

### 7.8 人工审核修改

#### 功能说明

人工审核用于判断脚本是否准确、安全、自然、可执行，并决定脚本后续状态。

#### 审核维度

| 审核项 | 判断标准 |
| --- | --- |
| 卖点准确性 | 是否忠实表达产品卖点 |
| 口播自然度 | 是否像真人会说的话 |
| 可拍摄性 | 分镜和素材是否可执行 |
| 平台适配度 | 是否符合目标平台风格 |
| 合规安全性 | 是否存在违规或夸大表达 |
| 转化明确性 | 是否有明确行动引导 |
| 创意质量 | 是否有记忆点和差异化 |

#### 审核动作

| 动作 | 说明 |
| --- | --- |
| 通过 | 进入脚本库，可交付剪辑或投放 |
| 小修后通过 | 编导直接编辑后通过 |
| 退回 AI 重写 | 选择退回原因，让 AI 定向优化 |
| 废弃 | 选题方向不成立，不再使用 |

#### 当前审核流转

| 审核状态 | 下一流程 | 系统动作 |
| --- | --- | --- |
| 通过 | T8 版本保存 -> T9 导出 | 保存为审核通过版本，进入脚本库和导出表 |
| 小修后通过 | 人工编辑 -> T8 版本保存 -> T9 导出 | 使用编辑框中的最新口播保存新版本 |
| 退回 AI 重写 | 退回 T5 脚本生成 | 保留退回原因，允许一键 AI 重新生成 |
| 废弃 | 记录原因 -> 停止交付 | 不进入优秀脚本库和导出交付 |

保存审核版本时，系统自动写入保存时间 `saved_at`，用户不需要手动填写时间。脚本生成时间 `generated_at` 在 AI 初稿生成时自动写入，文件导出时间 `exported_at` 在用户点击导出时自动写入。

在批量生成场景下，审核前必须明确当前选择脚本。若用户只是浏览脚本但未点击“选择此脚本”，系统应在交付前检查中提示“当前浏览未确认”，避免误保存非目标脚本。

#### 退回原因

系统支持选择结构化退回原因：

- Hook 不够强；
- 卖点表达不准确；
- 口播太像 AI；
- 分镜不可执行；
- 合规风险高；
- 转化引导弱；
- 不符合平台风格；
- 素材条件不支持；
- 创意同质化。

### 7.9 脚本版本管理

#### 功能说明

脚本从 AI 初稿到最终投放稿会经历多次修改，因此需要保留版本记录，便于追踪 AI 初稿与最终可用稿之间的差异。

#### 版本类型

| 版本类型 | 说明 |
| --- | --- |
| AI 初稿 | AI 第一次生成的原始脚本 |
| AI 重写稿 | 根据退回原因重新生成的版本 |
| 编导修改稿 | 编导人工编辑后的版本 |
| 审核通过稿 | 最终进入脚本库和导出的版本 |
| 投放使用稿 | 实际被剪辑或投放使用的版本 |

#### 版本记录字段

| 字段 | 说明 |
| --- | --- |
| version_no | 版本号 |
| source | AI 生成 / 人工修改 / AI 重写 |
| content_json | 当前版本完整内容 |
| change_summary | 修改说明 |
| editor | 修改人 |
| created_at | 创建时间 |
| generated_at | 脚本生成时间，由系统自动写入 |
| saved_at | 版本保存时间，由系统自动写入 |

### 7.10 脚本入库与导出

#### 功能说明

审核通过后的脚本进入脚本库，并支持导出给剪辑、直播和投放团队。

#### 脚本库字段

| 字段 | 说明 |
| --- | --- |
| 产品名称 | 关联产品 |
| 任务名称 | 关联内容任务 |
| 选题类型 | 痛点型、测评型、对比型等 |
| 平台 | 抖音、小红书、视频号等 |
| 内容目标 | 种草、转化、引流等 |
| 脚本状态 | 待审核、已通过、已导出、已投放 |
| 审核人 | 谁确认通过 |
| 风险标签 | 合规通过、需谨慎等 |
| 使用次数 | 是否被复用 |
| 更新时间 | 最近修改时间 |

#### 导出字段

MVP 阶段优先支持 CSV 或 Excel 导出，字段包括：

| 字段 | 是否在底部预览展示 | 是否在下载文件保存 | 说明 |
| --- | --- | --- | --- |
| 脚本 ID | 是 | 是 | 用于追踪版本和回填数据 |
| 脚本生成时间 | 是 | 是 | AI 生成时系统自动写入 |
| 版本保存时间 | 是 | 是 | 审核保存时系统自动写入 |
| 文件导出时间 | 是 | 是 | 点击导出时系统自动写入 |
| 产品名称 | 是 | 是 | 关联产品 |
| 平台 | 是 | 是 | 抖音、小红书等 |
| 选题标题 | 是 | 是 | 脚本标题或选题标题 |
| Hook | 是 | 是 | 前 3 秒吸引点 |
| 口播脚本 | 否 | 是 | 完整口播内容，下载文件保存 |
| 转化口播 | 否 | 是 | 行动引导话术 |
| 分镜建议 | 否 | 是 | 下载文件保存，底部预览不展示 |
| 字幕重点 | 否 | 是 | 下载文件保存，底部预览不展示 |
| 素材建议 | 否 | 是 | 下载文件保存，底部预览不展示 |
| 合规提醒 | 否 | 是 | 下载文件保存，底部预览不展示 |
| 待确认信息 | 否 | 是 | 下载文件保存，底部预览不展示 |
| 风险初筛命中 | 否 | 是 | 下载文件保存，底部预览不展示 |
| 生成模式 | 否 | 是 | Demo / DeepSeek 等 |
| 审核状态 | 是 | 是 | 通过、小修后通过、退回 AI 重写、废弃 |
| 审核人 | 否 | 是 | 责任人 |
| 版本号 | 是 | 是 | v1、v2 等 |
| 下一流程 | 否 | 是 | 审核状态对应的流转动作 |
| 质量总分 | 是 | 是 | 质量评分结果 |
| 质量等级 | 否 | 是 | A/B/C/D |

导出交互要求：

- 用户未勾选任何脚本时，默认导出全部脚本。
- 用户勾选部分脚本时，只导出所选脚本。
- 导出 CSV 和 Excel 的字段保持一致。
- 底部预览表保持摘要列，避免因分镜、字幕、素材等长字段造成页面拥挤。
- 同一个脚本 ID 在导出时应去重，避免脏数据导致重复导出。

## 8. 关键补充设计

### 8.1 产品事实依据与防胡编机制

为了降低 AI 胡编产品功效、价格、资质和活动信息的风险，MVP 阶段需要建立基础事实约束机制。

AI 生成内容必须遵循以下规则：

| 信息类型 | 生成规则 |
| --- | --- |
| 产品功效 | 只能基于已录入卖点和证明材料生成 |
| 价格权益 | 必须来自价格权益字段，不允许自行编造优惠 |
| 检测认证 | 必须来自证明材料字段，未提供则不能生成确定性表述 |
| 用户反馈 | 必须来自用户反馈或评论材料，不能虚构真实用户案例 |
| 平台规则 | 必须结合录入的合规要求和平台限制 |
| 未确认信息 | 标记为“需人工确认”，不能直接进入投放脚本 |

AI 输出中必须包含 `needs_confirmation` 字段，用于列出需要人工确认的信息。

### 8.2 Prompt 模板管理

Prompt 不应写死在代码中。MVP 可先保留基础模板配置能力，P1 建设轻量 Prompt 模板后台。

Prompt 模板需要支持：

| 能力 | 说明 |
| --- | --- |
| 模板分类 | 按平台、内容形式、业务目标区分 |
| 版本管理 | 每次修改 Prompt 都生成新版本 |
| 启用 / 停用 | 可切换当前使用模板 |
| 回滚 | 效果变差时可以回到旧版本 |
| 生成记录 | 每条脚本记录使用的 Prompt 版本 |

每条 AI 生成记录建议保存：

```text
prompt_template_id
prompt_version
model_name
input_snapshot
output_snapshot
generation_time
```

### 8.3 素材资产补充

脚本不仅要能写出来，还要能拍出来、剪出来。因此需要补充素材资产字段。

| 素材类型 | 示例 |
| --- | --- |
| 产品素材 | 产品图、包装图、使用图 |
| 证明素材 | 检测报告、资质截图、用户反馈 |
| 历史素材 | 过往短视频、直播切片、达人素材 |
| 待拍素材 | 需要拍摄的场景、人物、对比画面 |
| 禁用素材 | 版权不清晰或不能使用的素材 |

AI 输出分镜时建议标记：

- 已有素材可完成；
- 需要补拍；
- 需要运营提供证明材料；
- 存在素材缺口。

### 8.4 异常场景处理

| 异常场景 | 处理方式 |
| --- | --- |
| 产品信息不完整 | 阻止生成，并提示缺失字段 |
| AI 生成失败 | 支持重新生成 |
| AI 输出格式错误 | 自动重试或提示人工处理 |
| 风险词误报 | 支持人工标记为误报 |
| 选题全部不可用 | 支持重新生成选题池 |
| 审核长期未处理 | 标记为待跟进 |
| 导出失败 | 保留脚本状态，允许重新导出 |
| 投放数据缺失 | 标记为未回填，不参与效果分析 |

## 9. 页面设计

### 9.1 当前页面结构

当前 MVP 采用单页工作台，不再拆成多个独立页面。页面分为三层：

| 区域 | 说明 |
| --- | --- |
| 顶部核心链路 | 固定在页面上方，用户在任何滚动位置都能看到并跳转到对应模块 |
| 左侧输入区 | 承载任务创建和产品信息录入，保持宽度稳定 |
| 右侧工作区 | 按 T1 到 T9 顺序展示任务卡、卖点拆解、选题池、脚本生成、质量评分、风险初筛、审核保存、脚本库、数据复盘和导出 |

顶部核心链路用颜色区分阶段：

- 蓝色：P0 核心链路；
- 绿色：P1 增强能力。

按钮文案使用 T1、T2 等步骤标识，不在每个标题前重复写 P0。

### 9.2 布局原则

| 原则 | 要求 |
| --- | --- |
| 固定工作区 | 右侧模块的外层高度保持稳定，内容多时内部滚动、分页或轮播 |
| 顺序清晰 | 右侧模块按照核心链路顺序排列，不交叉错位 |
| 减少空白 | 模块内容少时不强行占满大面积；内容多时不撑开整个页面 |
| 操作可见 | 关键操作按钮固定在卡片底部或模块头部，不应被长内容挤出视野 |
| 预览克制 | 底部导出表只展示摘要字段，长字段进入下载文件 |

### 9.3 卖点拆解模块

卖点拆解不采用长列表，而是按分区卡片展示：

- 用户痛点；
- 使用场景；
- 核心利益点；
- 证明材料；
- 可用表达；
- 风险表达；
- 待确认信息。

用户可以在固定高度窗口内横向/分页浏览模块，每个模块展示条数和条目内容。

### 9.4 选题池模块

选题池使用卡片分页展示，用户可选择每页展示 1、2、3 或更多卡片。卡片结构为：

1. 内容角度和难度标签；
2. 选题标题；
3. Hook；
4. 推荐理由；
5. 风险提示；
6. 底部“选择此选题”按钮。

选择按钮固定在卡片底部；选中后显示“已选择”状态。内容角度和难度标签支持 hover 解释。

### 9.5 脚本生成模块

脚本生成模块支持单条和批量脚本：

- 批量脚本顶部显示脚本数量和脚本切换 tab；

## 11. AI 生成链路

### 11.1 当前三段式 AI 调用

MVP 阶段采用三段式 AI 调用：

1. 卖点拆解：输入产品信息，输出结构化卖点拆解。
2. 选题生成：输入任务目标、平台、目标用户和卖点拆解结果，输出选题池。
3. 脚本生成：输入选题、卖点、平台规则和内容形式，输出完整脚本。

三段式设计比一次性生成更稳定，可以降低直接生成时的偏题和胡编风险。

当前代码已接入 DeepSeek Chat Completions API，并保留本地 Demo 生成兜底。AI 生成失败、密钥未配置或返回字段不完整时，系统会使用后端兜底内容生成最低可用稿，避免页面出现空标题、空 Hook、空脚本或无法继续审核的状态。

### 11.2 Prompt 输入约束

AI 生成时必须传入以下上下文：

- 任务目标；
- 平台；
- 内容形式；
- 目标用户；
- 产品信息；
- 卖点拆解结果；
- 禁止表达；
- 合规要求；
- 证明材料；
- 当前 Prompt 模板版本；
- 平台策略矩阵；
- 业务目标策略矩阵；
- 内容形式策略矩阵。

Prompt 必须约束模型根据当前选择的平台、业务目标和内容形式调整生成标准，而不是只把字段值作为普通上下文传入：

| 约束维度 | 当前支持值 | 生成约束 |
| --- | --- | --- |
| 平台 | 抖音 / 小红书 / 视频号 / 快手 / B站 | 调整 Hook 强度、口播语气、转化承接、分镜节奏、字幕重点和素材建议 |
| 业务目标 | 种草 / 转化 / 直播引流 / 品牌曝光 | 调整脚本重心、CTA 强度、证明材料使用和质量评分标准 |
| 内容形式 | 口播 / 测评 / 对比 / 剧情 / 直播切片 | 调整脚本结构、镜头颗粒度、素材需求和禁用表达 |

### 11.3 输出格式约束

后端需要对 AI 输出进行结构化校验：

- JSON 是否合法；
- 必填字段是否完整；
- 数组字段是否为数组；
- 风险提示字段是否存在；
- 待确认信息字段是否存在；
- 是否包含未授权的功效、价格、资质或用户反馈表达。

校验失败时，系统优先自动重试；多次失败后提示人工处理。

当前已落地的输出保护包括：

- 对脚本标题、Hook、口播、分镜、字幕、素材、转化口播、合规提醒和待确认信息进行字段兜底；
- 分镜兜底必须绑定选题、Hook、痛点、场景、产品卖点和证明材料，避免生成默认化、无针对性的分镜；
- 批量生成后保留脚本列表，不因单条重写覆盖全部批量结果；
- 批量场景默认定位到已选选题对应脚本；
- 选中脚本后联动质量评分、风险初筛、人工审核和导出对象；
- 导出时将 AI 建议字段写入文件，但不在底部摘要表展示长字段。

### 11.4 质量不稳定的处理方向

为解决“质量不稳定、好脚本难沉淀、数据无法反向优化脚本”的问题，当前 MVP 已先补齐基础链路，后续 P1 需要继续强化：

| 问题 | 当前 MVP 处理 | P1 增强方向 |
| --- | --- | --- |
| 质量不稳定 | 结构化输入、固定输出字段、质量评分、人工审核 | Prompt 版本对比、失败样本库、评分维度权重可配置 |
| 好脚本难沉淀 | 审核保存版本、优秀脚本库入口、导出记录 | 高分脚本模板化、按平台/品类/内容形式检索 |
| 数据无法反向优化 | 数据复盘入口、反馈表、质量分与脚本关联 | 投放数据回填、效果标签、低表现归因、Prompt 迭代建议 |

### 11.5 平台策略矩阵

不同平台的脚本关注点不同，不能只把平台名称传给 AI。P0 需要在 Prompt 中加入平台策略矩阵，让 AI 在卖点拆解、选题生成、脚本生成、分镜建议、字幕重点和素材建议中都按平台调整。

| 平台 | 核心关注点 | 语气 | 内容结构 | 转化强度 | 素材重点 |
| --- | --- | --- | --- | --- | --- |
| 抖音 | 前 3 秒强 Hook、节奏快、痛点直接、转化动作明确 | 短句、强节奏、口语化 | Hook -> 痛点放大 -> 产品切入 -> 证据/体验 -> 明确行动 | 高 | 强字幕、产品近景、使用前后状态、手势或场景快切 |
| 小红书 | 真实体验、种草感、细节可信、避免硬广 | 像用户分享经验，弱推销、重细节 | 真实困扰 -> 选择理由 -> 使用体验 -> 适合人群 -> 温和建议 | 中 | 生活化场景、质地/使用细节、对比说明、笔记感字幕 |
| 视频号 | 信任感、稳健表达、日常适用和私域转化 | 表达克制、可信 | 场景共鸣 -> 可信解释 -> 产品价值 -> 温和引导 | 中 | 真人口播、产品展示、证明材料、适合熟人转发的字幕 |
| 快手 | 真实生活感、强口语化、场景直接、直播承接 | 接地气、像熟人推荐 | 生活场景 -> 痛点直说 -> 解决方案 -> 直播/购买承接 | 高 | 真实场景、手持产品、直播间权益提示、用户反馈截图 |
| B站 | 逻辑完整、测评解释、信息密度、弱转化 | 解释型、理性、信息充分 | 问题定义 -> 原理/测评 -> 对比分析 -> 结论建议 | 低 | 测评画面、成分/参数图、对比表、章节式字幕 |

当前 Prompt 需要同时包含：

- 平台策略矩阵：让模型理解不同平台的差异；
- 当前平台执行要求：把用户选择的平台提取成更具体的生成约束；
- 生成动作约束：要求模型按当前平台调整选题角度、Hook 强度、口播语气、转化口播、分镜建议、字幕重点和素材建议。

如果用户输入的平台不在矩阵中，系统按“最接近的平台内容习惯”兜底，优先保证真实感、表达可信和业务目标一致。

### 12.2.1 Prompt 实现思路

P0 阶段的 Prompt 不再只依赖单个大段文本，而是按公共约束模块拼装：

| Prompt 模块 | 作用 |
| --- | --- |
| 事实约束 | 禁止编造未提供的功效、价格、认证、用户反馈和活动规则 |
| 合规约束 | 避免绝对化、医疗化、夸大承诺、价格误导、外貌羞辱和攻击性表达 |
| 平台策略矩阵 | 说明抖音、小红书、视频号、快手、B站等平台的内容差异 |
| 当前平台执行要求 | 根据用户选择的平台生成更具体的 Hook、语气、结构、转化和素材要求 |
| 业务目标策略矩阵 | 说明种草、转化、直播引流和品牌曝光的评价标准与 CTA 强度 |
| 内容形式策略矩阵 | 说明口播、测评、对比、剧情和直播切片的结构与禁用表达 |
| 输出结构约束 | 统一要求 JSON 字段，包含口播、分镜、字幕、素材、转化口播、合规提醒和待确认信息 |

当前代码实现为公共函数 `build_platform_strategy_section(platform)`、`build_business_goal_strategy_section(business_goal)` 和 `build_content_type_strategy_section(content_type)`，并注入到四类 Prompt：

- 卖点拆解 Prompt；
- 选题生成 Prompt；
- 直接脚本生成 Prompt；
- 基于已选选题的脚本生成 Prompt。

这样做的目的是把平台差异、业务目标差异和内容形式差异从“模型自己猜”变成“系统明确约束”，提升 P0 质量稳定性，并为 P1 的 Prompt 模板后台和平台效果复盘打基础。

## 14. 非功能需求

### 14.1 可用性

- 核心生成流程尽量控制在 3 步内完成：产品信息 -> 选题 -> 脚本。
- 表单字段应支持示例提示，降低运营录入成本。
- AI 生成结果必须可编辑，不强制用户接受。
- 风险提示应直接定位到具体文本位置。
- 顶部核心链路在页面滚动时保持可见。
- 右侧模块按 T1 到 T9 顺序排列，不出现交叉错位。
- 选题卡片、脚本模块和风险列表在内容较多时内部滚动或分页，不撑破整体布局。

### 14.2 稳定性

- AI 生成失败时应支持重试。
- AI 输出格式错误时应自动校验并重试。
- 导出失败不应影响脚本状态和内容保存。
- 关键编辑动作应自动保存。
- 批量生成后重新生成单条脚本，不应丢失原批量列表。
- 选择选题后批量生成脚本，应保持选题上下文，不生成空白脚本。
- Supabase 连接不可用时，本地 Demo 不应完全不可用，应能回退到 JSONL。

### 14.3 合规与安全

- AI 生成内容不得绕过人工审核直接进入投放。
- 所有价格、功效、资质、活动信息必须由人工确认。
- 风险词库支持持续维护。
- 脚本版本、审核动作和生成记录需要留痕。
- `.env.local` 不进入版本库。
- Supabase 服务密钥只用于服务端，不暴露到前端。

- 任务创建；
- 产品信息录入；

## 16. 风险与取舍

| 风险 | 说明 | 应对方式 |
| --- | --- | --- |
| AI 胡编产品事实 | AI 可能虚构功效、价格、资质或用户反馈 | 建立事实依据字段和待确认信息机制 |
| 脚本看起来好但不可拍 | AI 分镜可能不符合实际素材和拍摄条件 | 增加素材建议、素材缺口和可拍摄性审核 |
| 合规风险 | 美妆、食品、医疗等行业容易出现违规表达 | 规则词库 + AI 风险解释 + 人工审核 |
| Prompt 效果不稳定 | 不同平台和内容目标需要不同生成结构 | 建立 Prompt 模板版本和生成记录 |
| MVP 过大 | 协同、数据、素材、模板同时建设会拖慢上线 | P0 聚焦核心生成和审核导出链路 |

## 17. 总结

AI 编导脚本生成工具的核心价值，不是简单替代编导写文案，而是重构短视频脚本生产流程。

MVP 阶段应重点解决四个问题：

1. 将运营提供的零散产品卖点结构化，减少信息传递损耗。
2. 通过 AI 生成选题池和脚本初稿，降低编导从零发散和撰写的成本。
3. 通过人工审核、风险词初筛、事实依据约束和结构化退回原因，保证脚本质量和合规安全。
4. 通过脚本版本保存和基础脚本库，让优质脚本可以沉淀、复用，并为后续数据反馈和模板优化打基础。

因此，本产品应设计成一个“AI 辅助的短视频内容生产工作台”，而不是单点的 AI 文案生成器。长期方向是形成“内容任务管理、脚本生成、审核协同、资产沉淀、数据反馈和模板优化”的完整闭环，帮助团队稳定、高效、可持续地产出短视频脚本。

截至当前版本，P0 已从“生成一个脚本”推进到“任务 -> 产品 -> 卖点 -> 选题 -> 批量脚本 -> 选择脚本 -> 质量评分 -> 风险初筛 -> 人工审核 -> 版本保存 -> 部分/全量导出 -> Supabase 留痕”的闭环。P1 已完成质量评分、优秀脚本库和数据复盘的入口及基础结构，但仍属于增强能力初版，下一阶段重点应放在真实投放数据回流、优秀脚本沉淀规则、Prompt 版本管理和风险词库运营化。
