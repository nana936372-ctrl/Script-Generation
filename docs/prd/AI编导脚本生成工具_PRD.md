| 项目 | 内容 |

## 2. 项目背景

短视频内容生产需求持续增长，编导团队每天需要围绕不同产品卖点，产出多个短视频选题和脚本，并交付给剪辑、直播和投放团队执行。

现有流程主要依赖人工完成：

```text
产品/运营提供卖点 -> 编导人工想选题 -> 编导人工写脚本 -> 手动整理表格 -> 交给剪辑、直播和投放团队执行
```

当前流程暴露出以下问题：

1. 编导需要从零理解产品、拆解卖点、构思选题和撰写脚本，前期创意发散和初稿生产耗时较长。
2. 不同编导对同一卖点的理解和表达方式不一致，导致脚本质量不稳定，容易出现卖点表达不清、口播不自然、转化引导弱、分镜不可执行等问题。
3. 优质脚本没有形成结构化沉淀，往往散落在表格、文档或聊天记录中，后续难以复用。
4. 投放后的播放、点击、转化、ROI、评论反馈等数据没有有效回流到脚本生产环节，团队难以判断哪些选题、结构和表达方式更有效。
5. 编导、运营、剪辑、直播和投放之间协同成本较高，脚本交付格式不统一，容易产生返工。

因此，本工具希望通过 AI 生成能力和结构化流程设计，将短视频脚本生产从“人工经验驱动”升级为“标准化输入 + AI 辅助生成 + 人工审核 + 脚本资产沉淀 + 数据反馈优化”的内容生产工作台。

## 3. 产品定位

### 3.1 产品定义

AI 编导脚本生成工具是一个面向短视频内容生产团队的 AI 辅助工作台，帮助团队完成从内容任务创建、产品卖点结构化、选题生成、脚本初稿生成、风险初筛、人工审核、脚本入库、导出交付到数据反馈的完整流程。

本产品不是单点 AI 文案生成器，而是服务内容生产链路的协同工具。

### 3.2 核心价值

| 价值方向 | 说明 |
| --- | --- |
| 提升初稿效率 | AI 辅助完成卖点拆解、选题生成和脚本初稿生成，降低编导从零创作成本 |
| 标准化信息输入 | 将运营提供的零散卖点结构化为目标用户、用户痛点、使用场景、证明材料、价格权益和合规限制 |
| 提升交付质量 | 输出口播、分镜、字幕重点、素材建议、转化口播和风险提示，减少后续沟通返工 |
| 沉淀脚本资产 | 保存审核通过脚本，并通过产品、平台、内容目标、选题类型、效果标签等字段支持复用 |
| 数据反哺生产 | 将投放数据和退回原因回流到脚本库、Prompt 模板和风险词库，持续优化内容生产方法 |

### 3.3 MVP 目标

MVP 阶段重点验证一条核心链路：

```text
任务创建 -> 产品信息录入 -> AI 卖点拆解 -> AI 选题生成 -> AI 脚本生成 -> 风险词初筛 -> 人工编辑审核 -> 脚本版本保存 -> CSV/Excel 导出
```

MVP 不追求自动剪辑、自动投放、复杂权限、多平台投放系统对接或模型训练，优先验证 AI 生成结果是否能被编导小修后使用，以及是否能降低内容生产和交付成本。

### 5.3 P2 暂不纳入

| 功能模块 | 后置原因 |
| --- | --- |
| 自动剪辑 | 依赖素材质量、画面理解、素材管理和剪辑工具集成，开发成本较高 |

| 自动训练高转化模型 | 早期脚本库和效果数据不足，不适合直接训练模型 |

## 6. 核心业务流程

### 6.1 主流程

```text
创建内容任务
-> 产品卖点录入
-> AI 卖点拆解
-> AI 生成选题池
-> 编导筛选选题
-> AI 生成脚本
-> 风险初筛
-> 人工审核修改
-> 脚本版本保存
-> 脚本入库
-> 导出交付
-> 投放数据回填
-> 效果标签沉淀
-> 模板优化
```

MVP 阶段做到“导出交付”为止，投放数据回填、效果标签和模板优化作为 P1 逐步建设。

### 6.2 状态流转

```text
待创建 -> 待录入产品信息 -> 待拆解卖点 -> 待生成选题 -> 待筛选选题 -> 待生成脚本 -> 待审核 -> 小修中 -> 已通过 -> 已导出
```

退回重写流程：

```text
待审核 -> 退回 AI 重写 -> 重新生成 -> 待审核
```

P1 投放流程：

```text
已导出 -> 已投放 -> 待回填 -> 已回填 -> 已复盘
```

## 7. 功能需求

### 7.1 内容任务创建

#### 功能说明

运营、产品或业务负责人创建内容生产任务，明确本次脚本生产的业务目标、平台、人群、内容形式、数量、截止时间和审核责任人。

#### 输入字段

| 字段 | 类型 | 是否必填 | 示例 |
| --- | --- | --- | --- |
| 任务名称 | 文本 | 是 | 618 洁面乳短视频脚本 |
| 业务目标 | 单选 | 是 | 种草 / 转化 / 直播引流 / 品牌曝光 |
| 产品名称 | 文本 | 是 | 氨基酸洁面乳 |
| 目标用户 | 文本 | 是 | 18-30 岁油敏肌女生 |
| 投放平台 | 多选 | 是 | 抖音 / 小红书 / 视频号 |
| 内容形式 | 单选/多选 | 是 | 口播 / 剧情 / 测评 / 对比 / 直播切片 |
| 脚本数量 | 数字 | 是 | 5 |
| 截止时间 | 日期时间 | 否 | 今日 18:00 |
| 审核人 | 人员 | 否 | 编导负责人 / 业务负责人 |

#### 输出结果

系统生成内容任务卡片，明确本次任务的目标、平台、人群、数量、审核责任人和当前状态。

### 7.2 产品信息录入

#### 功能说明

运营或产品负责人录入产品基础信息，作为后续 AI 生成选题和脚本的事实依据。

#### 输入字段

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 产品名称 | 文本 | 是 | 本次推广产品 |
| 核心卖点 | 多行文本 | 是 | 产品主推优势 |
| 目标用户 | 多行文本 | 是 | 主要消费人群 |
| 使用场景 | 多行文本 | 否 | 用户在什么情况下使用 |
| 价格权益 | 多行文本 | 否 | 价格、优惠、赠品、活动信息 |
| 证明材料 | 多行文本/附件 | 否 | 检测报告、用户反馈、品牌背书等 |
| 平台限制 | 多行文本 | 否 | 不同平台表达要求 |
| 禁止表达 | 多行文本 | 否 | 禁止使用或慎用表达 |
| 合规要求 | 多行文本 | 否 | 行业限制和审核要求 |

#### 输出结果

形成标准化产品信息卡，并作为 AI 卖点拆解、选题生成和脚本生成的基础输入。

### 7.3 AI 卖点拆解

#### 功能说明

AI 根据产品信息，将运营语言转化为编导可用的脚本语言。

#### 输出字段

| 字段 | 说明 |
| --- | --- |
| 用户痛点 | 用户为什么需要这个产品 |
| 使用场景 | 用户在什么场景下会产生需求 |
| 核心利益点 | 产品能给用户带来的直接价值 |
| 证明材料 | 哪些内容可以增强可信度 |
| 可用表达 | 可以安全使用的表达方式 |
| 风险表达 | 可能存在合规风险的表达方式 |
| 待人工确认信息 | 价格、功效、证明材料、活动规则等需要人工确认的信息 |

#### 输出格式示例

```json
{
  "pain_points": [],
  "scenarios": [],
  "benefits": [],
  "proof_points": [],
  "safe_expressions": [],
  "risky_expressions": [],
  "needs_confirmation": []
}
```

### 7.4 AI 选题生成

#### 功能说明

AI 根据任务目标、平台、目标用户、内容形式和卖点拆解结果，批量生成可供编导筛选的选题池。

#### 选题类型

| 类型 | 适合场景 | 示例 |
| --- | --- | --- |
| 痛点型 | 转化投放 | 为什么你洗完脸总觉得紧绷？ |
| 测评型 | 种草内容 | 油敏肌洁面实测：洗完到底拔不拔干？ |
| 对比型 | 产品差异明显 | 便宜洁面和温和洁面的区别在哪？ |
| 场景型 | 日常消费品 | 熬夜后满脸油，早上怎么洗才舒服？ |
| 反常识型 | 提高停留 | 脸越洗越油，可能不是你没洗干净 |
| 直播引流型 | 直播间转化 | 今晚直播间这支洁面适合哪些人抢？ |

#### 每个选题输出字段

| 字段 | 说明 |
| --- | --- |
| 选题标题 | 给编导看的方向 |
| 前 3 秒 Hook | 用于吸引用户停留 |
| 内容角度 | 痛点、测评、对比、场景等 |
| 适合平台 | 抖音、小红书、视频号等 |
| 推荐理由 | 为什么适合这个产品 |
| 风险提示 | 是否存在表达风险 |
| 拍摄难度 | 低 / 中 / 高 |

### 7.5 编导筛选选题

#### 功能说明

编导从 AI 生成的选题池中选择适合本次任务的方向，进入脚本生成环节。

#### 筛选维度

| 维度 | 判断标准 |
| --- | --- |
| 是否符合业务目标 | 是否适合种草、转化或引流 |
| 是否贴合目标用户 | 用户是否有真实痛点 |
| 是否适合平台 | 是否符合目标平台内容风格 |
| 是否可拍摄 | 是否能在现有素材和条件下完成 |
| 是否有风险 | 是否涉及夸大、医疗化或绝对化表达 |
| 是否有差异化 | 是否避免同质化内容 |

### 7.6 AI 脚本生成

#### 功能说明

选题确定后，AI 根据固定脚本结构生成初稿。

#### 脚本结构

1. 前 3 秒 Hook；
2. 用户痛点放大；
3. 产品卖点切入；
4. 场景化说明；
5. 信任补充；
6. 转化行动引导。

#### 输出字段

| 字段 | 使用角色 | 说明 |
| --- | --- | --- |
| 口播脚本 | 编导 / 主播 | 完整口播内容 |
| 分镜建议 | 剪辑 / 拍摄 | 每个时间段画面怎么呈现 |
| 字幕重点 | 剪辑 | 哪些句子需要突出 |
| 素材建议 | 剪辑 / 拍摄 | 产品特写、对比画面、场景素材等 |
| 转化口播 | 投放 / 主播 | 引导点击、购买、进直播间 |
| 合规提醒 | 审核人 | 需要人工确认的风险表达 |
| 待确认信息 | 审核人 | 价格、功效、证明材料等需确认内容 |

#### 输出格式示例

```json
{
  "title": "",
  "hook": "",
  "spoken_script": "",
  "storyboard": "",
  "subtitle_points": [],
  "material_suggestions": [],
  "conversion_cta": "",
  "risk_notes": [],
  "needs_confirmation": []
}
```

### 7.7 风险词初筛

#### 功能说明

系统对 AI 生成脚本进行风险初筛，标记潜在风险表达，并给出替代表达建议。

#### 检查类型

| 风险类型 | 示例 |
| --- | --- |
| 绝对化表达 | 最好、第一、永久、彻底 |
| 夸大承诺 | 立刻见效、马上变白、根治 |
| 医疗化表达 | 治疗、修复疾病、改善炎症 |
| 价格误导 | 全网最低、错过不再有 |
| 资质风险 | 未经确认的认证、检测、背书 |

#### 实现方式

MVP 阶段采用“规则词库 + 大模型复核”的方式：

1. 规则词库扫描脚本文本，标记命中风险词。
2. AI 根据命中风险词解释风险原因。
3. 系统给出建议替代表达。
4. 人工审核时可确认风险、修改文本或标记误报。

### 7.8 人工审核修改

#### 功能说明

人工审核用于判断脚本是否准确、安全、自然、可执行，并决定脚本后续状态。

#### 审核维度

| 审核项 | 判断标准 |
| --- | --- |
| 卖点准确性 | 是否忠实表达产品卖点 |
| 口播自然度 | 是否像真人会说的话 |
| 可拍摄性 | 分镜和素材是否可执行 |
| 平台适配度 | 是否符合目标平台风格 |
| 合规安全性 | 是否存在违规或夸大表达 |
| 转化明确性 | 是否有明确行动引导 |
| 创意质量 | 是否有记忆点和差异化 |

#### 审核动作

| 动作 | 说明 |
| --- | --- |
| 通过 | 进入脚本库，可交付剪辑或投放 |
| 小修后通过 | 编导直接编辑后通过 |
| 退回 AI 重写 | 选择退回原因，让 AI 定向优化 |
| 废弃 | 选题方向不成立，不再使用 |

#### 退回原因

系统支持选择结构化退回原因：

- Hook 不够强；
- 卖点表达不准确；
- 口播太像 AI；
- 分镜不可执行；
- 合规风险高；
- 转化引导弱；
- 不符合平台风格；
- 素材条件不支持；
- 创意同质化。

### 7.9 脚本版本管理

#### 功能说明

脚本从 AI 初稿到最终投放稿会经历多次修改，因此需要保留版本记录，便于追踪 AI 初稿与最终可用稿之间的差异。

#### 版本类型

| 版本类型 | 说明 |
| --- | --- |
| AI 初稿 | AI 第一次生成的原始脚本 |
| AI 重写稿 | 根据退回原因重新生成的版本 |
| 编导修改稿 | 编导人工编辑后的版本 |
| 审核通过稿 | 最终进入脚本库和导出的版本 |
| 投放使用稿 | 实际被剪辑或投放使用的版本 |

#### 版本记录字段

| 字段 | 说明 |
| --- | --- |
| version_no | 版本号 |
| source | AI 生成 / 人工修改 / AI 重写 |

## 8. 关键补充设计

### 8.1 产品事实依据与防胡编机制

为了降低 AI 胡编产品功效、价格、资质和活动信息的风险，MVP 阶段需要建立基础事实约束机制。

AI 生成内容必须遵循以下规则：

| 信息类型 | 生成规则 |
| --- | --- |
| 产品功效 | 只能基于已录入卖点和证明材料生成 |
| 价格权益 | 必须来自价格权益字段，不允许自行编造优惠 |
| 检测认证 | 必须来自证明材料字段，未提供则不能生成确定性表述 |
| 用户反馈 | 必须来自用户反馈或评论材料，不能虚构真实用户案例 |
| 平台规则 | 必须结合录入的合规要求和平台限制 |
| 未确认信息 | 标记为“需人工确认”，不能直接进入投放脚本 |

AI 输出中必须包含 `needs_confirmation` 字段，用于列出需要人工确认的信息。

### 8.2 Prompt 模板管理

Prompt 不应写死在代码中。MVP 可先保留基础模板配置能力，P1 建设轻量 Prompt 模板后台。

Prompt 模板需要支持：

| 能力 | 说明 |
| --- | --- |
| 模板分类 | 按平台、内容形式、业务目标区分 |
| 版本管理 | 每次修改 Prompt 都生成新版本 |
| 启用 / 停用 | 可切换当前使用模板 |
| 回滚 | 效果变差时可以回到旧版本 |
| 生成记录 | 每条脚本记录使用的 Prompt 版本 |

每条 AI 生成记录建议保存：

```text
prompt_template_id
prompt_version
model_name
input_snapshot
output_snapshot
generation_time
```

### 8.3 素材资产补充

脚本不仅要能写出来，还要能拍出来、剪出来。因此需要补充素材资产字段。

| 素材类型 | 示例 |
| --- | --- |
| 产品素材 | 产品图、包装图、使用图 |
| 证明素材 | 检测报告、资质截图、用户反馈 |
| 历史素材 | 过往短视频、直播切片、达人素材 |
| 待拍素材 | 需要拍摄的场景、人物、对比画面 |
| 禁用素材 | 版权不清晰或不能使用的素材 |

AI 输出分镜时建议标记：

- 已有素材可完成；
- 需要补拍；
- 需要运营提供证明材料；
- 存在素材缺口。

### 8.4 异常场景处理

| 异常场景 | 处理方式 |
| --- | --- |
| 产品信息不完整 | 阻止生成，并提示缺失字段 |
| AI 生成失败 | 支持重新生成 |
| AI 输出格式错误 | 自动重试或提示人工处理 |
| 风险词误报 | 支持人工标记为误报 |
| 选题全部不可用 | 支持重新生成选题池 |
| 审核长期未处理 | 标记为待跟进 |
| 导出失败 | 保留脚本状态，允许重新导出 |
| 投放数据缺失 | 标记为未回填，不参与效果分析 |

## 11. AI 生成链路

### 11.1 三段式 AI 调用

MVP 阶段采用三段式 AI 调用：

1. 卖点拆解：输入产品信息，输出结构化卖点拆解。
2. 选题生成：输入任务目标、平台、目标用户和卖点拆解结果，输出选题池。
3. 脚本生成：输入选题、卖点、平台规则和内容形式，输出完整脚本。

三段式设计比一次性生成更稳定，可以降低直接生成时的偏题和胡编风险。

### 11.2 Prompt 输入约束

AI 生成时必须传入以下上下文：

- 任务目标；
- 平台；
- 内容形式；
- 目标用户；
- 产品信息；
- 卖点拆解结果；
- 禁止表达；
- 合规要求；
- 证明材料；
- 当前 Prompt 模板版本。

### 11.3 输出格式约束

后端需要对 AI 输出进行结构化校验：

- JSON 是否合法；
- 必填字段是否完整；
- 数组字段是否为数组；
- 风险提示字段是否存在；
- 待确认信息字段是否存在；
- 是否包含未授权的功效、价格、资质或用户反馈表达。

校验失败时，系统优先自动重试；多次失败后提示人工处理。

## 14. 非功能需求

### 14.1 可用性

- 核心生成流程尽量控制在 3 步内完成：产品信息 -> 选题 -> 脚本。
- 表单字段应支持示例提示，降低运营录入成本。
- AI 生成结果必须可编辑，不强制用户接受。
- 风险提示应直接定位到具体文本位置。

### 14.2 稳定性

- AI 生成失败时应支持重试。
- AI 输出格式错误时应自动校验并重试。
- 导出失败不应影响脚本状态和内容保存。
- 关键编辑动作应自动保存。

### 14.3 合规与安全

- AI 生成内容不得绕过人工审核直接进入投放。
- 所有价格、功效、资质、活动信息必须由人工确认。
- 风险词库支持持续维护。
- 脚本版本、审核动作和生成记录需要留痕。

### 15.1 阶段一：MVP 原型

## 16. 风险与取舍

| 风险 | 说明 | 应对方式 |
| --- | --- | --- |
| AI 胡编产品事实 | AI 可能虚构功效、价格、资质或用户反馈 | 建立事实依据字段和待确认信息机制 |
| 脚本看起来好但不可拍 | AI 分镜可能不符合实际素材和拍摄条件 | 增加素材建议、素材缺口和可拍摄性审核 |
| 合规风险 | 美妆、食品、医疗等行业容易出现违规表达 | 规则词库 + AI 风险解释 + 人工审核 |
| Prompt 效果不稳定 | 不同平台和内容目标需要不同生成结构 | 建立 Prompt 模板版本和生成记录 |
| MVP 过大 | 协同、数据、素材、模板同时建设会拖慢上线 | P0 聚焦核心生成和审核导出链路 |

## 17. 总结

AI 编导脚本生成工具的核心价值，不是简单替代编导写文案，而是重构短视频脚本生产流程。

MVP 阶段应重点解决四个问题：

1. 将运营提供的零散产品卖点结构化，减少信息传递损耗。
2. 通过 AI 生成选题池和脚本初稿，降低编导从零发散和撰写的成本。
3. 通过人工审核、风险词初筛、事实依据约束和结构化退回原因，保证脚本质量和合规安全。
4. 通过脚本版本保存和基础脚本库，让优质脚本可以沉淀、复用，并为后续数据反馈和模板优化打基础。

因此，本产品应设计成一个“AI 辅助的短视频内容生产工作台”，而不是单点的 AI 文案生成器。长期方向是形成“内容任务管理、脚本生成、审核协同、资产沉淀、数据反馈和模板优化”的完整闭环，帮助团队稳定、高效、可持续地产出短视频脚本。
